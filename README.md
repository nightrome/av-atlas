# AV Atlas

A dashboard of autonomous vehicle (AV) research: who's publishing, which
institutions and countries are active, how topics have shifted over time, and
which papers matter most *within AV research specifically*. Built from the
complete proceedings of major computer vision/robotics venues, not a
keyword-filtered subset — see [about.html](about.html) (or the
live About page) for exactly how papers are found, classified, and
scored.

[![tests](https://github.com/nightrome/av-atlas/actions/workflows/tests.yml/badge.svg)](https://github.com/nightrome/av-atlas/actions/workflows/tests.yml)

## Downloading the data

The whole corpus is published as four gzipped CSVs — papers, authorship
edges, the in-corpus citation edge list, and institutions, joined on
`paper_id`. They are linked from the site's About page, generated by
`scripts/build_data_release.py` on every build, and documented (including
what the numbers are *not*) in the README that ships alongside them.

Read that README before using them. In short: citation counts are internal to
this corpus and incomplete, affiliations are resolved for a minority of
papers, author names are not disambiguated, and every classification is
automated rather than reviewed.

## Running the site locally

The site is static HTML/JS/CSS (under `site/`) with no backend — it just reads a
`stats.json` served alongside it. `build_public_site.py` assembles `public/` from
`site/` plus a fresh `stats.json`; serve that:

```bash
python scripts/build_public_site.py   # once, to produce public/
cd public && python -m http.server 8747
```

then open `http://localhost:8747/index.html`. `stats.json` is regenerated by the
pipeline below and is gitignored (too large, and reproducible from the scripts),
so a fresh clone needs at least one full pipeline run before the site has data to
show.

## Deploying

```bash
python scripts/deploy.py
```

Runs the full build/test pipeline (see below), commits and pushes any
source changes to `main`, then publishes `public/` to the `gh-pages`
branch. Live at https://nightrome.github.io/av-atlas/.

## The pipeline

Five stages, run roughly in order (see the About page for the full
diagram and detail):

1. **Collect** — `fetch_cvf.py`, `fetch_neurips.py`, `fetch_dblp_listing.py`,
   `fetch_ieee_openalex.py`, `fetch_arxiv.py`, etc. pull complete venue
   proceedings from each source's own site — no keyword filtering.
2. **Merge & classify** — `merge_corpus.py` dedupes across sources;
   `classify.py` assigns a category and an AV-relevance label.
3. **Enrich** — `fetch_cvf_affiliations.py` / `fetch_affiliations_arxiv.py`
   (author affiliations), `fetch_orcids.py`, `fetch_s2_author_ids.py` for
   AV-relevant papers only.
4. **Citation graph** — `build_citation_graph.py` (in-corpus reference-list
   parsing) and `fetch_semanticscholar_citing.py` (reverse-citation
   discovery, which can also surface new paper titles that feed back into
   step 1).
5. **Aggregate** — `aggregate.py` writes `data/stats.json`, which every page
   in this directory reads from.

## Setup

```bash
pip install -r scripts/requirements.txt
```

Some enrichment scripts (`fetch_semanticscholar_citing.py`,
`fetch_s2_author_ids.py`, `fetch_orcids.py`) need a free Semantic Scholar API
key — copy `.env.example` to `.env` and fill it in (get a key at
https://www.semanticscholar.org/product/api). `.env` is gitignored; never
commit a real key.

## Tests

```bash
python scripts/run_tests.py
```

Runs the Python unit tests (`scripts/tests/`, stdlib `unittest`), the pure-JS
logic tests (`tests/*.test.js`, plain Node, no install needed), and a
13-page smoke test that loads every page's script against real data and
checks nothing throws.

The same command runs in CI on every push and pull request
(`.github/workflows/tests.yml`). The smoke, regression and detail-page tests
need `data/stats.json`, which is gitignored and rebuilt by the pipeline, so
on a fresh checkout they are skipped with a printed notice rather than
failing — a full run needs `scripts/build_public_site.py` first.

## Reporting a data error

Every page has a "spot an error?" link that opens an email pre-filled with
the page you were on — use it for anything wrong with a specific paper,
author, or institution.
